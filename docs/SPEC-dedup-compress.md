# clayfs: 重複排除・圧縮・アーカイブ退避の仕様

2026-10-11 に決めた内容。実装はこの分岐 (`experiment/dedup-compress`) で行う。

## 方針

- 読み書きの経路には何も挟まない。`~/src` は素の APFS のまま使う。
- 圧縮と重複排除は、あとからまとめて行う保守処理にする (`git gc` と同じ位置づけ)。
- 圧縮は **APFS の透過圧縮** を使う。zstd の自前の保管庫と restic は採用しない。
- 縮まないファイルは、そのまま格納する。

## 計測値 (2026-10-11、作業ツリー 7.86GB、約 26.9 万ファイル)

| 状態 | サイズ |
|---|---|
| 現在 | 7.86GB |
| 重複排除だけ | 6.39GB |
| 圧縮だけ (64KiB ごとの zlib) | 4.24GB |
| 重複排除 + 圧縮 | 3.73GB |

`archive/` の 1.83GB は圧縮済みで縮まない。計測は `experiments/measure.py` (読み取りのみ)。

## 確かめた前提 (イメージのボリューム上で実験)

- `ditto --hfsCompression --noclone` で圧縮できる (テキストで 35%)。`--noclone` が無いと、
  同じボリューム内では clone されて圧縮されない。
- 圧縮済みファイルの clone は、圧縮されたまま共有される。
- 追記や 1 バイトの書き換えで、そのファイルだけ非圧縮に戻る。clone 元は無傷。
- 同じボリューム内の移動、tar の往復では圧縮が保たれる。`cp -p` の写しは非圧縮になる。
- 属性だけを別のファイルへ写しても、「圧縮の印だけ付いて読めない」状態にはならない。

## 共通の土台

- コミット時に、変更されたファイルの SHA-256 を記録する。
  - 変更検出を「サイズと更新時刻」頼みから確実なものにする。
  - `dedup` と `scrub` は、この記録を使う (毎回ハッシュを取り直さない)。
- 圧縮したファイルは、読み戻してハッシュが一致することを確かめてから、元と差し替える。

## コマンド

### `clayfsctl dedup [--dry-run]`

- 中身が同じファイルを clone にまとめる。対象は作業ツリーの中と、コミットとの間。
- 圧縮のあとにも走らせる (圧縮で作り直された実体へ、コミット側を付け替える)。
- 属性 (権限、時刻、xattr) は元のまま残す。

### `clayfsctl compress [パス...]`

- 対象: 7 日以上更新のないファイルと、圧縮を保つパス (`keep`) の下の全ファイル。
- 除外: 圧縮済みの形式、データベース、1 ブロックに収まる小さいファイル、開かれているファイル。
- 書き込まれたファイルは OS が非圧縮に戻すので、次回また対象になる。圧縮を保つパスの下なら、年齢に関係なく再圧縮される。

### `clayfsctl keep パス...` / `unkeep パス...`

- 対象は作業ツリーの中の任意のパス（ディレクトリでもファイルでもよい。`.` は全体）。
- `keep`: パスを圧縮を保つ対象として `keep.json` に記録し、直ちに圧縮する。場所は動かさず、そのまま読める。
- `unkeep`: 対象から外し、残りの対象に含まれないファイルだけを非圧縮に戻す。引数なしの `keep` は一覧を表示する。
- 記録はストアの `keep.json` にパスの一覧として持つ。以前の `parked.json` は、初回の読み込みで移す。

### `clayfsctl scrub`

- 記録したハッシュと中身を照合する。圧縮の印が付いているのに読めないファイルも検出する。
- `quota.db` (圧縮の印だけ付いて読めなくなっていたファイル) の原因が未解明なので、必須とする。

#### `clayfsctl scrub --layers` (コミットの中にしか無い古い版)

- APFS にはユーザーデータのチェックサムが無い。コミットは作業ツリーのクローンで、変更されていないファイルは作業ツリーと領域を共有するので、
  作業ツリーの検査で足りる。足りないのは、**変更されて作業ツリーと分かれた古い版**で、レイヤーの中にしか残らない。
- 索引に `versions` (パス・大きさ・更新時刻・ハッシュ・どのレイヤーか・最後に検査した時刻) を持つ。
  - コミット時に、追加・変更されたファイルを、**レイヤー側のコピーから**ハッシュして記録する (索引がある場合)。
  - 索引ができる前のコミットは、最初の `scrub --layers` が `lstat` だけで拾い (読み出しなし)、ハッシュは検査のときに取る。
- 検査は、作業ツリーの現在の版と違うものだけを見る。その版を持つレイヤーは、記録したレイヤーが残っていればそれ、無ければ古い順に探す。
  どのレイヤーにも無くなった版 (gc 済み) は、記録から消す。記録したレイヤーが残っているのにファイルが無ければ、問題として報告する。
- `--budget-mb N`: 検査していない順・古い順に N MB だけ検査して終わる。
- 自動実行 (`clayfsctl run`) は、電源につながっていて、前回から `CLAYFS_SCRUB_LAYERS_INTERVAL` (既定 1 日) 空いたとき、
  `CLAYFS_SCRUB_LAYERS_MB` (既定 4096) ずつ検査する。問題があれば `STORE/layers-scrub.broken` と `clayfsctl info` に出す。
- 修復はしない (バックアップが別にある前提)。実ストアでの見積もり: 8 コミット・約 27 万ファイルの拾い出しは約 50 秒、古い版を持つパスは 48 個。

### `clayfsctl rebuild --fresh | --replay`

イメージを作り直す。全ファイルを圧縮した状態で入れ直し、スパースバンドルを詰める。

- `--fresh`: 履歴を引き継がない。今の状態を最初のコミットにする。
- `--replay`: 履歴を再生する。古いコミットから順に、変更一覧に沿って適用し直す。
- **両方を実装し、マシン負荷への影響を比べる**: 所要時間、CPU 時間、ディスクの最大使用量、
  出来上がったイメージのサイズ。
- 比べた結果（作業ツリー 約 8GB、約 29 万ファイル）:

  | 項目 | `--fresh` | `--replay` |
  |---|---|---|
  | 所要時間（経過） | 458 秒 | 504 秒 |
  | CPU 時間 | 332 秒 | 265 秒 |
  | ボリュームの使用量 | 5.74 GB | 6.19 GB |
  | イメージのサイズ | 8.3G | 8.7G |
  | 残るコミット | 1 個 | 5 個 |

- **使い分け**: 容量を最小にしたいとき、履歴が要らないときは `--fresh`。過去のコミットを残したいとき、
  過去の状態を戻す可能性があるときは `--replay`。どちらも同じ作業ツリーの状態を再現する。
- 実行中は `~/src` を使うサービスを止める。一時的に 2 つ分の容量を使う。
- 入れ替えは、新しいイメージの中身（コミットの一覧と `scrub`）を確かめてから行う。

## アーカイブ

- 置き場所を `~/src/archive` から **`~/src-archive`** (イメージの外、内蔵ディスク) に移す。
- 退避先: `lenovo:Users/yashi/mac/src-archive`
- 手元に残すもの: 各プロジェクトの最新 1 本と、作成から 7 日以内のもの。
- それ以外を、古い順に 1 本ずつ `rclone move` で送る (転送後に照合してから手元を消す)。
- 相手に届かない晩は失敗して終わり、翌晩にやり直す。
- 退避したファイルの名前、サイズ、ハッシュ、退避先を、手元の目録に 1 行ずつ記録する。

## 毎日 3 時の保守 (LaunchAgent)

1. `commit`
2. `compress`
3. `dedup`
4. アーカイブの退避
5. 週 1 回だけ `scrub` と `compact`

- 電源につながっているときだけ動かす。
- `compact` はマウントを外す必要があるので、使用中なら何もしない。
- スリープで時刻を過ぎた場合は、次に起きたときに 1 回だけ走る (launchd の動作)。
- `cfsctl maintain` (4 時) とは重ならない。

## やらないこと

- 自前の保管庫 (zstd) と、古いコミットの詰め直し。コミットは clone のままにする。
- restic への書き出し。
- 読み書きの経路への介入 (FUSE)。

## 実装の順番

1. ハッシュの記録、`dedup`、`scrub`
2. `keep` / `unkeep`、`compress`
3. `rebuild` の 2 方式と負荷の比較
4. アーカイブの移動と退避、3 時の保守

## 残っている懸念

- `quota.db` の壊れ方は再現できていない。
- 圧縮済みの大きなファイルに 1 バイト書くと、ファイル全体が非圧縮に書き直される。
  頻繁に書き換える大きなファイルは対象から外す。
- `cp -p` などで別の場所へ写すと非圧縮になる (害はないが、効果は消える)。
